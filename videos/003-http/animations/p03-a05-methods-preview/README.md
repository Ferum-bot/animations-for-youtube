## Визуальное устройство

Сохранены утверждённые синий фон, мятные акценты, рамки и мягкая прозрачность справа. Все содержательные элементы находятся слева, в зоне x=136…1256; подложка полностью прозрачна начиная с x=1740. Движение объясняет действие: появление метода, доставка запроса, замена представления, изменение поля. Объём PUT — небольшое смещение входящего слоя, без декоративного постоянного движения.

## Техническая точность

- Восемь методов — основной набор RFC 9110, а не полный реестр IANA. PATCH определён RFC 5789 и является стандартным расширением HTTP.
- Безопасность относится к запрашиваемой семантике. Сцена не утверждает отсутствие журналирования и любых внутренних побочных действий. Изменяющий баланс GET явно обозначен нарушением.
- Идемпотентность PUT показана через одинаковое итоговое состояние. PATCH не назван обязательно неидемпотентным: `replace /city → Kazan` сам по себе идемпотентен.
- CORS-пример — запрос JSON PATCH между двумя origin без credentials. Ему нужен preflight. Неуспешный OPTIONS не разрешает отправить основной PATCH; curl не применяет браузерную CORS-политику.
- Подписи уточняют исходную речь: не любой cross-origin запрос требует preflight; CORS не заменяет защиту от CSRF; фактический ответ PATCH также должен содержать Allow-Origin.
- OPTIONS — общий HTTP-метод. Специфичен для браузера здесь механизм CORS preflight.
- Показан отдельный браузерный кэш результатов preflight, не HTTP-кэш ответов OPTIONS. Origin, метод и заголовки показаны для одного фиксированного URL и режима без credentials; это не исчерпывающий перечень ключей кэша. Линия срока условная, не задаёт реальное числовое ограничение браузера.

Основания: [RFC 9110, методы](https://www.rfc-editor.org/rfc/rfc9110.html#section-9), [RFC 5789, PATCH](https://www.rfc-editor.org/rfc/rfc5789.html), [Fetch, CORS protocol](https://fetch.spec.whatwg.org/#http-cors-protocol), [Fetch, preflight cache](https://fetch.spec.whatwg.org/#cors-preflight-cache).

## Архитектура и проверка

Жизненный цикл, аудио и фон используют существующие `NarratedHttpScene` и `HttpStage`. `shared/methods` содержит голосовые тайминги; `shared/HttpDiagram.tsx` — общую рамку, маршруты, сообщения и смену подписей без наложений. Представление профиля переиспользуется для тела PUT и состояния ресурса. CORS разделён на проблему, объяснение и модель голосовых якорей. Компоненты оставлены внутри HTTP: оснований переносить их в глобальные пакеты пока нет. Состояние вычисляется из текущего кадра, без таймеров и случайности.

QA: ключевые PNG находятся в `out/qa/http/methods/`, сценарии воспроизведения — `out/qa/http/methods-qa.cjs` и `methods-qa-final.cjs`. Проверяются вход, первое читаемое состояние, смены смысла и подписей, удержания, выход, фото ведущего, светлый/тёмный фон, прозрачность справа и повторное получение того же кадра. После одобрения пользователя четыре отдельные сцены экспортированы штатным premultiplied ProRes 4444 процессом CapCut. Общая композиция остаётся просмотром в редакторе.
