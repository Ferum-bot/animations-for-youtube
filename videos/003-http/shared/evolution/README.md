# Эволюция HTTP: главы 7 и 8

Шесть самостоятельных сцен и два отдельных просмотра с исходной озвучкой. Утверждённая палитра выпуска, 2560×1440, 30 fps; содержание x=136…1256, фон плавно становится полностью прозрачным к x=1740. Все движения зависят от кадра, без случайности и непрерывных декоративных циклов.

## Разделители

Объясняющая графика не пересекает разделители. Начала первых сцен сдвинуты к концам существующих переходов: глава 7 — 887100 мс, глава 8 — 978400 мс. Это на 73 и 106 мс позже начал блоков Whisper; первые произнесённые слова по токенам начинаются позже этих границ. Семантические якоря продолжают ссылаться на абсолютные позиции слов исходной записи.

Глава 7 заканчивается на 968124 мс. Далее до 978400 мс нет объясняющих сцен; внутри этого промежутка находится разделитель «HTTP/2 и HTTP/3» (973900…978400 мс). Два preview не склеены: каждый воспроизводит только свою главу, с одной аудиодорожкой. Если монтажные паузы изменятся, относительные якоря глав остаются полезными, а абсолютную позицию CapCut нужно уточнить при экспорте.

## Технические решения

- У HTTP/1.0 показана базовая модель с закрытием соединения; существование расширения keep-alive не отрицается. Постоянство HTTP/1.1 — поведение по умолчанию, не бесконечное существование TCP.
- Pipelining подписан как возможность HTTP/1.1, а не типичная работа современных браузеров. Обе направляющие — два направления одного TCP. Ответы не меняют порядок.
- График в сравнении схематичен: отражает повторный старт новых TCP, не утверждает отмену congestion control в постоянном соединении. Числовой шкалы и фиктивных измерений нет.
- Шесть соединений обозначены как типичный браузерный лимит, не ограничение HTTP. Макет страницы использует те же именованные ресурсы.
- В HTTP/2 исходный `200 OK` — смысловое представление ответа перед перекодированием, не строка бинарного wire format. Разбор кадра явно неполный. HEADERS содержит закодированные поля, тело занимает несколько DATA. ID 1/3/5 обозначают потоки; порядковые обозначения DATA 1/2/3 — наглядные части примера, не поле заголовка кадра.
- Кадры ответов чередуются внутри одного TCP, затем маршрутизируются по stream ID. На общей линии порядок не меняется; разные ответы завершаются в разное время. Тело нельзя считать переданным целиком по одному HEADERS.
- В TCP отображаются условные участки байтов, а не номера HTTP-кадров. Получение последующих участков не означает их выдачи приложению до закрытия пропуска. После недостающих данных граница выдачи продвигается.
- QUIC сохраняет порядок внутри каждого потока. В примере потеря относится только к потоку картинки; остальные могут продолжать доставку. Это не обещание отсутствия congestion control, задержек зависимых запросов или блокировок QPACK.
- Существующая обложка видео о транспорте в репозитории не найдена. Использована законченная типографическая вставка TCP/QUIC, без выдуманной обложки, просмотров и длительности. Настоящие YouTube-ссылка и подсказка добавляются при публикации; графика не создаёт их.

Источники, проверенные при разборе: [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.3), [RFC 9113](https://www.rfc-editor.org/rfc/rfc9113.html#section-5), [RFC 9114](https://www.rfc-editor.org/rfc/rfc9114.html#section-2), [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.3), [MDN о соединениях](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Connection_management_in_HTTP_1.x).

## Разделение ответственности

`timing.ts` читает якоря и длительности из JSON. `EvolutionScene` собирает общую сцену. `Elements` содержит геометрию каналов, блоков данных и меток завершения, `ResourcePage` — макет страницы. Переходы состояний и содержание находятся рядом с соответствующими Composition. Существующие HttpStage, HttpPartPreview, HttpElements, HttpDiagram и временные функции переиспользуются. Глобальные пакеты и старые главы не меняются.

QA находится в `out/qa/http/evolution`: ключевые состояния, переходы, появление и исчезновение, светлый/тёмный фон, проверка прозрачности справа и повторных кадров. Отдельная проверка сравнивает кадры полного Overlay с самостоятельными разделителями и проверяет отсутствие графики в паузе. В этой итерации видеофайлы не экспортируются.


## Результат приёмки

Проверены 86 ключевых кадров шести сцен, 72 кадра на прозрачной/светлой/тёмной подложке, повторные состояния и границы двух preview. Последние кадры пусты; в контрольных кадрах альфа справа от x=1740 равна нулю. Повторные ключевые кадры совпадают побайтово. Во время разделителей активен только соответствующий chapter-divider; промежуток между главами не содержит объясняющей графики. Сравнение 10 контрольных кадров полного Overlay и отдельных разделителей совпало с точностью сглаживания: только 7 пикселей отличаются на 1/255 в одном кадре, альфа совпадает точно. Три кадра паузы полностью прозрачны.

`task check` и `git diff --check` проходят; остаётся прежнее предупреждение об отсутствующем аудио другого DNS-видео. Редактор на порту 9000 отвечает HTTP 200. Рефакторинг сохранил геометрию в библиотеке выпуска, тайминги — в anchors/metadata, а смысловые состояния — в папках сцен. Старые главы и глобальные компоненты не изменялись.
