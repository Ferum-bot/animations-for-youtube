# HTTP: анонс и переходы

Первый рабочий проход по выбранному направлению «Знаки протокола», палитра «Ночной синий и мята». Размер 2560×1440, 30 fps. Все состояния зависят только от времени композиции и сериализуемых props.

## Просмотр

Анонс и проверочные композиции собраны в папке `P-00`, десять переходов — в `P-01-Perehody`.

- `Video-003-http-p00-a02-agenda-preview` — анонс поверх предоставленного кадра, с оригинальным аудио. Длительность 23.433 с, соответствует 00:15.300–00:38.733 текущего WAV.
- `Video-003-http-p00-a01-episode-agenda` — тот же анонс с реальной прозрачностью, со звуком для проверки. Для видеомастера звук можно отключить через `withAudio: false`.
- `Video-003-http-p00-a03-chapter-preview` — пример полноэкранного перехода с появлением и исчезновением на предоставленном кадре, 4.5 с.
- `P-01-Perehody` — общая папка редактора с десятью отдельными переходами и заголовками по содержанию речевых блоков.
- `Video-003-http-Overlay` — исходная запись целиком и текущая расстановка графики. Монтажные паузы сохранены; это не финально собранное видео.

Редактор: `pnpm --filter @channel/remotion exec remotion studio src/index.tsx --port=9000 --no-open`.

Фотография используется только в явно обозначенных preview-композициях. Она не является частью прозрачного анонса или полноэкранных производственных композиций. Исходный скриншот хранится без изменения; интерфейс плеера обрезается рамкой превью в CSS.

## Прозрачность и композиция

По запросу пользователя анонс расширен под посадку ведущего справа: текст и скобки находятся между x=136 и x=1256. Ширина рамки увеличена с 860 до 1120 px; размер текста пунктов — с 49 до 62 px, заголовка — с 70 до 84 px, деталей — на 22%. Фон остаётся плотным до x=1300, плавно теряет непрозрачность и становится полностью прозрачным при x≥1740; лицо на предоставленном референсе находится правее. Градиент относится только к фону, не размывает текст и не окрашивает лицо. Все элементы анонса исчезают на последнем кадре. Переходы между главами остаются полноэкранными, как было согласовано ранее.

## Синхронизация

Единственный источник голосовых якорей — `anchors.json`, а расстановка и длительности — `timeline.json`. `shared/agendaContent.ts` читает эти якоря и описывает расположение строк и смысловые состояния. Основание — токены первого локального Whisper-блока, а не равные интервалы.

| Фраза | Позиция в текущем WAV |
| --- | --- |
| «В этом видео» | 00:15.560; вход графики начинается в 00:15.300 |
| «из чего состоит HTTP» | 00:17.290 |
| «методы» | 00:19.260 |
| «тело» | 00:22.480 |
| «эволюцию» | 00:26.580 |
| «возьмём один конкретный запрос» | 00:31.760 |

Пункты появляются последовательно. На слове «тело» акцент возвращается к «Устройство HTTP», а миниатюра показывает границу тела. Затем появляются версии и путь запроса. Это автоматические слуховые ориентиры Whisper; окончательная редакторская проверка пользователем ещё впереди.

Временные паузы не сокращались. Каждый 4.5-секундный переход помещён в конец своей паузы и заканчивается примерно за 0.1–0.2 с до речи. После перемонтажа пауз нужно обновить абсолютные якоря. Названия и номера десяти частей предложены по расшифровке и доступны для редакторского изменения в `shared/chapters.ts`.

## Код

`studioFolder` в `animation.json` задаёт необязательную папку в редакторе. Для десяти разделителей указана `P-01-Perehody`: текущая версия Remotion не поддерживает кириллицу в именах папок. Без этого поля сохраняется группировка `P-NN`. Папка редактора не меняет ID, положение в таймлайне или размещение исходников.

- `shared/theme.ts` — локальная вариация токенов `@channel/theme` и размеры области ведущего.
- `shared/HttpStage.tsx` — фон, плавная альфа-маска и отдельная подложка для проверки.
- `shared/MessageBrackets.tsx` — единая геометрия скобок и мятной метки.
- `shared/ProtocolDetail.tsx` — строго типизированные маленькие иллюстрации HTTP.
- `shared/timing.ts` — преобразование кадров во время и ограниченные функции перехода; использует `@channel/motion-core`.
- `shared/HttpChapterDivider.tsx` — общий жизненный цикл перехода, отдельные главы предоставляют только содержание.
- `animations/p00-a01-episode-agenda/` — анонс и опциональное воспроизведение исходного аудио.

Аудио встроенного полного Overlay воспроизводится один раз: timeline явно выключает аудио внутри анонса. Превью использует тот же анонс, не копию реализации. Для статического QA у анонса также есть `previewBackground: 'light' | 'dark' | 'presenter' | 'transparent'`.

`GET / HTTP/1.1` показывается как фрагмент стартовой строки, а не полный запрос. `47 45 54` — UTF-8/ASCII букв GET. `7B 7D` — байты пустого объекта `{}` без пробелов. Пример `{"id":42}` имеет длину 9 байт. Линии версий — условные знаки для анонса, не количественная схема соединений.

## Выполненная проверка

`task check`: структура, таймлайны и строгий TypeScript. Известное предупреждение старого DNS-выпуска об отсутствующем аудио не относится к HTTP.

Обновлённая расширенная версия проверена в файлах `out/qa/http/wide-*.png`.

В `out/qa/http/` сохранены только QA-изображения и служебная сборка: вход, первое читаемое состояние, все пять смысловых состояний анонса, переходы между ними, удержание и выход; жизненный цикл разделителя; все десять заголовков; анонс на светлом, тёмном фоне и на кадре ведущего. Стиллы рендерились в половинном масштабе для просмотра, метаданные композиций — QHD.

После расширения повторная пиксельная проверка десяти alpha-кадров подтвердила нулевую альфу справа от x=1740 и полностью пустые первый/последний кадры анонса. Два независимых рендера состояния на кадре 400 совпали пиксель в пиксель. Визуально проверены кириллица, длинные названия, скобки, миниатюры и область лица.

После реализации выполнен проход по повторениям и соседним компонентам репозитория: все HTTP-детали и превью остаются в библиотеке этого выпуска; используются существующие общие токены/функции движения. Дубли голосовых таймингов удалены из TS. Глобальные компоненты, старые видео и восемь эталонов не переделывались. Реестр обновлён штатным генератором.

Видеоклипы и полный видеорендер не запускались. Коммит и push не выполнялись.

## Исправление экспорта для CapCut (13 сентября 2026)

В первоначальном ProRes RGB был straight/unassociated. На почти прозрачном хвосте градиента RGB менялся, например, до `(0, 85, 85)` при альфе `3/255`. Обычный PNG-композит скрывал эти значения, но в CapCut появлялись цветные полосы и светлый ореол. Пользователь подтвердил чистый край после преобразования RGB в premultiplied перед кодированием.

Окончательный комплект пересобран из исходных PNG в `renders/003-http/CapCut-2K-30fps-v2/`, 11 MOV без звука, 2560×1440, 30 fps. Для этого используется общий модуль `scripts/capcut-prores.mjs`: Remotion выводит PNG, полный FFmpeg из PATH выполняет `premultiply` в 16-битном RGB и кодирует ProRes 4444. Встроенный FFmpeg Remotion не содержит этого фильтра. Не применять преобразование повторно к готовым premultiplied-файлам.

Штатный путь для будущих клипов: `task render:capcut VIDEO=003-http ANIMATION=p00-a01-episode-agenda`. Он автоматически запускает `scripts/check-capcut-alpha.mjs` после экспорта. Проверка анализирует RGB относительно альфы в декодированных кадрах, включая вход и выход. Старый дефектный файл не проходит эту проверку. Для оглавления дополнительно проверяется полная прозрачность при x≥1740.

Для просмотра premultiplied MOV через обычный PNG-композитор сначала нужен корректный unpremultiply; иначе сам QA-процесс затемнит мягкие края. Проверку в целевом редакторе это не заменяет. QA новой версии: `out/qa/http/encoded-v2/`, `export-verification-v2.json`.
