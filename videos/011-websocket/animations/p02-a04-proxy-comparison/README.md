# Прокси и сквозная пересылка

В Studio открыть `Video-011-websocket-p02-a04-proxy-comparison`. До слова «вот» в кадре ведущий. На монтажном времени 07:34,880 таблица начинает появляться и к слову «таблице» видна целиком. После слова «журнала» в 07:56,940 таблица плавно исчезает. За основу взята таблица «Почему вид звена важен разработчику» из темы 2 материалов выпуска. Строка про адрес клиента остаётся видимой во время разбора остальных трёх строк.

Монтажный интервал 07:31,500–07:57,840 соответствует 07:23,500–07:49,840 исходного WAV. Подсветка включается в 07:38,020, 07:43,300 и 07:50,540 монтажного времени. В каждой озвученной строке акцент переходит от названия к ответам слева направо. Во время реплики текст соответствующей ячейки увеличивается на 15 % и окрашивается в кобальтовый цвет. К концу реплики он возвращается к обычному размеру и цвету. Чтобы восстановить озвучку для Studio, выполнить из корня проекта

```sh
ffmpeg -ss 443.5 -i ~/Movies/CapCut/websocket_audio.WAV -t 26.34 -ac 1 -ar 48000 -c:a aac -b:a 96k apps/remotion/public/generated/011-websocket/proxy-comparison.m4a
```

У прокси TCP keepalive на стороне клиента и сервера настраивается отдельно. Состояние и таймер записи относятся к звеньям, отслеживающим потоки. Строка о перезапуске прокси описывает остановку процесса, которому принадлежат действующие соединения. [HAProxy, option tcpka](https://docs.haproxy.org/3.2/configuration.html#4-option%20tcpka) · [Linux, таймеры conntrack](https://docs.kernel.org/networking/nf_conntrack-sysctl.html) · [Google Cloud, сквозная пересылка](https://docs.cloud.google.com/load-balancing/docs/passthrough-network-load-balancer)
